Coder, comparer, décomposer, corriger

  // (Source unique : scripts/test_exercices.R évalue cette même cellule avec Node.)
  const today = new Date().toISOString().slice(0, 10);
  const hash = (s) => {
    let h = 1779033703 ^ s.length;
    for (let i = 0; i < s.length; i++) { h = Math.imul(h ^ s.charCodeAt(i), 3432918353); h = (h << 13) | (h >>> 19); }
    return h >>> 0;
  };
  const mulberry32 = (a) => () => {
    a |= 0; a = (a + 0x6d2b79f5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
  return (id, salt = 0, day = today) => {
    const u = mulberry32(hash(`${day}|${id}|${salt}`));
    const int = (a, b) => a + Math.floor(u() * (b - a + 1));
    const pick = (arr) => arr[Math.floor(u() * arr.length)];
    const normal = () => Math.sqrt(-2 * Math.log(1 - u())) * Math.cos(2 * Math.PI * u());
    return { u, int, pick, normal };
  };
}

Terrain de jeu : simuler une ville

Avec kappa = Inf il n’y a aucune ségrégation structurelle, pourtant D et M ne sont pas nuls : c’est le biais d’échantillonnage (voir plus bas).

Parts de chaque groupe et indice D sur 6 quartiers

Marche 1 sur 6 · Guidé

seg0 = { const g = rng("seg-d-0", salt); return { seed: g.int(1, 9999) }; }

Une ville compte 6 quartiers. Les vecteurs a (groupe A) et b (groupe B) donnent les effectifs par quartier. Calcule la part de chaque groupe qui vit dans chaque quartier, puis l’indice D de Duncan, et repère le quartier qui contribue le plus.

AstuceIndice 1 · par où commencer

On compare deux répartitions : celle du groupe A entre les quartiers, celle du groupe B. Pour cela, divise chaque effectif par le total de son groupe.

AstuceIndice 2 · les formules

pa <- a / sum(a) et pb <- b / sum(b) ; \(D\) est la moitié de sum(abs(pa - pb)).

Raisonnement.

  1. Les effectifs bruts ne se comparent pas (un quartier peut être plus peuplé) ; on compare des parts de chaque groupe : \(a_i/A\) et \(b_i/B\). Chacun de ces vecteurs somme à 1.
  2. Si les deux groupes se répartissent de la même façon, \(a_i/A = b_i/B\) partout et \(D = 0\).
  3. Chaque quartier contribue par l’écart absolu \(|a_i/A - b_i/B|\) ; \(D\) est la moitié de la somme de ces écarts.
  4. Lecture : \(D\) est la part de A (ou de B) qui devrait déménager pour égaliser les deux répartitions.
  5. which.max(abs(pa - pb)) désigne le quartier le plus « déséquilibré » : c’est lui qui contribue le plus à \(D\).
set.seed(seg0$seed) a <- sample(5:80, 6); b <- sample(5:80, 6) pa <- a / sum(a) # répartition du groupe A entre les quartiers pb <- b / sum(b) # répartition du groupe B D <- 0.5 * sum(abs(pa - pb)) c(D = D, quartier_max = which.max(abs(pa - pb))) 
set.seed(seg0$seed)
a <- sample(5:80, 6); b <- sample(5:80, 6)
pa <- a / sum(a)                   # répartition du groupe A entre les quartiers
pb <- b / sum(b)                   # répartition du groupe B
D  <- 0.5 * sum(abs(pa - pb))
c(D = D, quartier_max = which.max(abs(pa - pb)))

Pièges fréquents.

  • Calculer des parts dans le quartier (\(a_i/(a_i+b_i)\)) : c’est une mesure d’exposition ou d’isolement, pas D.
  • Oublier la valeur absolue : la somme des écarts signés vaut toujours 0.
  • Oublier le facteur \(1/2\) : D dépasserait 1 en cas de séparation complète.

Pour aller plus loin. À l’étape suivante tu écris cette formule comme une fonction valable pour n’importe quelle table, et tu la testes sur des cas limites.

Coder l’indice D de Duncan

Marche 2 sur 6 · À compléter

seg1 = { const g = rng("seg-d-1", salt); return { seed: g.int(1, 9999), kappa: g.pick([2, 4, 8]) }; }

Pour deux groupes, \(D = \frac12 \sum_i \left|\frac{a_i}{A} - \frac{b_i}{B}\right|\) où \(a_i, b_i\) sont les effectifs de l’unité \(i\) et \(A, B\) les totaux. Écris my_D() ; elle sera testée sur plusieurs villes, pas seulement sur celle affichée.

AstuceIndice 1 · par où commencer

D compare, quartier par quartier, la part du groupe A et la part du groupe B. Calcule d’abord ces deux vecteurs de parts (chacun somme à 1), puis agrège les écarts.

AstuceIndice 2 · la formule

0.5 * sum(abs(a / sum(a) - b / sum(b))). Interprétation : part minimale de l’un des groupes qui devrait déménager pour égaliser les répartitions.

Raisonnement.

  1. \(a_i/A\) est la part du groupe A qui vit dans l’unité \(i\) ; \(b_i/B\) celle du groupe B. Chacune somme à 1 sur l’ensemble des unités.
  2. Si les deux groupes sont répartis de la même façon, tous les écarts sont nuls et \(D = 0\).
  3. Si les groupes sont totalement séparés, chaque unité n’abrite qu’un groupe : \(\sum_i |\cdot| = 2\), et le facteur \(1/2\) ramène \(D\) à 1.
  4. Lecture : \(D\) est la part minimale d’un groupe qui devrait déménager pour égaliser les deux répartitions.
  5. La fonction est testée sur quatre tables, dont la séparation totale (\(D = 1\)) et l’intégration parfaite (\(D = 0\)).
source("R/segregation.R") tab <- seg_sim_city(U = 40, size = 150, p = 0.3, kappa = seg1$kappa, seed = seg1$seed) my_D <- function(tab) { a <- tab[, 1]; b <- tab[, 2] 0.5 * sum(abs(a / sum(a) - b / sum(b))) } c(mon_D = my_D(tab), seg_D = seg_D(tab)) 
source("R/segregation.R")

Pièges fréquents.

  • Oublier la valeur absolue : la somme des écarts signés vaut toujours 0.
  • Calculer des parts à l’intérieur de chaque unité (\(a_i/(a_i+b_i)\)) : c’est une autre famille de mesures (exposition, isolement).
  • Interpréter un D élevé sans tenir compte de la taille des unités : D est biaisé vers le haut quand les unités sont petites (exercice « Biais de petites unités »).

Pour aller plus loin. Calcule D sur la même ville après avoir regroupé les unités deux à deux : D baisse. C’est le problème d’unité spatiale modifiable (MAUP), traité par l’exercice de décomposition.

Entropie d’une composition

Marche 3 sur 6 · Guidé

seg00 = { const g = rng("seg-m-0", salt); return { p: g.pick([0.1, 0.2, 0.3, 0.4]) }; }

Écris la fonction entropie(p) (entropie de Shannon, logarithme naturel, convention 0 ln 0 = 0) puis évalue-la sur quatre compositions : un groupe seul, deux groupes de parts et , deux groupes égaux, trois groupes égaux.

AstuceIndice 1 · par où commencer

Une composition très diverse (parts égales) doit donner une grande valeur, une composition « pure » doit donner 0. Pense à une somme de termes de la forme \(p \ln p\).

AstuceIndice 2 · la formule

\(E = -\sum_g p_g \ln p_g\) : en R, -sum(p * log(p)) après avoir retiré les parts nulles.

Raisonnement.

  1. \(E(p) = -\sum_g p_g \ln p_g\) est maximale quand tous les groupes sont également présents (elle vaut alors \(\ln G\)) et nulle quand un seul groupe est présent.
  2. Valeurs de contrôle : composition séparée \(0\) ; deux groupes à parts égales \(\ln 2 \approx 0{,}693\) ; trois groupes égaux \(\ln 3 \approx 1{,}099\).
  3. p[p > 0] applique la convention \(0\ln 0 = 0\) ; sans elle, 0 * log(0) vaut NaN et le résultat entier est perdu.
  4. Dans l’indice \(M\), \(E\) est l’entropie de la ville entière et \(E_i\) celle du quartier \(i\). \(M\) mesure de combien les quartiers sont moins divers que la ville.
entropie <- function(p) { p <- p[p > 0] # convention 0 * log(0) = 0 -sum(p * log(p)) } p <- seg00$p c(separee = entropie(c(1, 0)), deux_groupes = entropie(c(p, 1 - p)), egal2 = entropie(c(0.5, 0.5)), egal3 = entropie(rep(1 / 3, 3))) 
entropie <- function(p) {
  p <- p[p > 0]                  # convention 0 * log(0) = 0
  -sum(p * log(p))
}
p <- seg00$p
c(separee = entropie(c(1, 0)), deux_groupes = entropie(c(p, 1 - p)),
  egal2 = entropie(c(0.5, 0.5)), egal3 = entropie(rep(1 / 3, 3)))

Pièges fréquents.

  • Oublier le signe moins : l’entropie serait négative.
  • Ne pas filtrer les zéros : NaN dès qu’une part est nulle (cas très fréquent dans les quartiers homogènes).
  • Mélanger log, log2 et log10 : cela change l’échelle (nats, bits, dits), pas le classement, à condition de rester cohérent d’un indice à l’autre.

Pour aller plus loin. L’étape suivante combine cette fonction quartier par quartier pour construire M, avec un nombre quelconque de groupes.

Coder l’indice d’information mutuelle M

Marche 4 sur 6 · À compléter

seg2 = { const g = rng("seg-m-1", salt); return { seed: g.int(1, 9999) }; }

\(M = E - \sum_i t_i E_i\) avec \(E\) l’entropie de la composition globale, \(E_i\) celle de l’unité \(i\), \(t_i\) la part de la population dans l’unité \(i\) (entropie de Shannon, log naturel). Écris my_M() pour un nombre quelconque de groupes.

AstuceIndice 1 · par où commencer

M est une « information mutuelle » : l’entropie globale moins l’entropie moyenne locale. La fonction entropie est fournie ; il te faut trois ingrédients : \(E\), les \(E_i\) et les poids \(t_i\).

AstuceIndice 2 · la formule

E <- entropie(colSums(tab) / sum(tab)), Ei <- apply(tab / rowSums(tab), 1, entropie), ti <- rowSums(tab) / sum(tab). Contrôle : si toutes les unités ont la même composition, \(M = 0\) ; si les groupes sont totalement séparés, \(M = E\).

Raisonnement.

  1. \(E = -\sum_g p_g \ln p_g\) mesure la diversité de la composition de toute la ville.
  2. \(E_i\) est la même quantité calculée dans l’unité \(i\).
  3. \(M = E - \sum_i t_i E_i\) est la réduction moyenne de diversité quand on connaît l’unité : plus les unités sont homogènes, plus \(M\) est grand.
  4. Bornes : \(M = 0\) si chaque unité a la composition globale ; \(M = E\) si chaque unité est « pure ». D’où \(H = M/E \in [0,1]\).
  5. Le calcul est valable pour un nombre quelconque de groupes (matrice à \(G\) colonnes), contrairement à D.
source("R/segregation.R") set.seed(seg2$seed) tab3 <- matrix(rpois(8 * 3, 25) + 1, 8, 3) entropie <- function(p) { p <- p[p > 0]; -sum(p * log(p)) } my_M <- function(tab) { E <- entropie(colSums(tab) / sum(tab)) Ei <- apply(tab / rowSums(tab), 1, entropie) ti <- rowSums(tab) / sum(tab) E - sum(ti * Ei) } c(mon_M = my_M(tab3), seg_M = seg_M(tab3))

entropie <- function(p) { p <- p[p > 0]; -sum(p * log(p)) }
my_M <- function(tab) {
  E  <- entropie(colSums(tab) / sum(tab))
  Ei <- apply(tab / rowSums(tab), 1, entropie)
  ti <- rowSums(tab) / sum(tab)
  E - sum(ti * Ei)
}
c(mon_M = my_M(tab3), seg_M = seg_M(tab3))

Pièges fréquents.

  • Pondérer les \(E_i\) par la part du groupe au lieu de la part de population \(t_i\) de l’unité.
  • Mélanger log, log2 et log10 : l’échelle change ; reste cohérent avec seg_M (logarithme naturel).
  • Oublier la convention \(0 \ln 0 = 0\) : sans p[p > 0], une part nulle donne NaN.

Pour aller plus loin. M est décomposable exactement entre et intra zones : c’est l’exercice de décomposition, en fin de page.

Biais de petites unités par Monte-Carlo

Marche 5 sur 6 · Autonome

Dans une ville sans ségrégation structurelle (kappa = Inf), calcule la valeur moyenne de D sous allocation aléatoire pour des unités de 5 puis de 500 habitants. Instructions exactes (pour que la correction soit déterministe) : seg_sim_city(U = 100, size = s, p = 0.3, kappa = Inf, seed = 1) puis mean(seg_null(tab, B = 100, stat = seg_D, seed = 2)).

AstuceIndice 1 · par où commencer

Dans cette ville aucune ségrégation n’a été « mise » : les groupes sont répartis au hasard. Que vaut D « attendu » dans ce cas ? Pas 0. Réfléchis à ce que produit le hasard dans de petites unités.

AstuceIndice 2 · la formule

mean(seg_null(tab, B = 100, stat = seg_D, seed = 2)). Que conclure d’un D observé de 0,25 dans une ville dont les unités comptent 5 habitants ?

Raisonnement.

  1. Avec des unités de 5 habitants, la part du groupe B varie énormément d’une unité à l’autre par pur hasard (0 %, 20 %, 40 %…).
  2. D mesure ces écarts à la moyenne : il est donc mécaniquement positif, même sans ségrégation.
  3. seg_null réalloue au hasard les individus entre les unités (en gardant leurs tailles) et recalcule D ; la moyenne sur 100 allocations est le niveau attendu sous H0.
  4. Le biais décroît quand la taille des unités augmente, en gros comme l’inverse de sa racine carrée.
  5. Conséquence pratique : on ne compare jamais deux D sans benchmark quand la taille des unités diffère entre villes ou dates, ou alors on corrige (Carrington-Troske, inférence d’Allen et al.).
source("R/segregation.R") tailles <- c(petit = 5, grand = 500) res <- sapply(tailles, function(s) { tab <- seg_sim_city(U = 100, size = s, p = 0.3, kappa = Inf, seed = 1) mean(seg_null(tab, B = 100, stat = seg_D, seed = 2)) }) round(res, 3)

  • Utiliser une seule allocation aléatoire : il faut moyenner sur \(B\) allocations (ici 100).
  • Oublier les graines : la correction attend seed = 1 pour la ville et seed = 2 pour seg_null.

Décomposer M entre et intra zones

Marche 6 sur 6 · Autonome

seg4 = { const g = rng("seg-decomp-1", salt); return { seed: g.int(1, 9999) }; }

Une ville a 12 unités regroupées en 3 zones. Vérifie à la main l’identité \(M = M_{\text{inter}} + \sum_r \frac{N_r}{N} M_r\) où \(M_{\text{inter}}\) est le \(M\) calculé sur les zones agrégées et \(M_r\) le \(M\) à l’intérieur de la zone \(r\).

AstuceIndice 1 · par où commencer

Deux regards sur la même ville : à l’échelle des zones (unités agrégées) et à l’intérieur de chaque zone. Prépare d’abord la table des effectifs agrégés par zone.

AstuceIndice 2 · la formule

rowsum(tab, zone) trie les zones par ordre alphabétique ; split() aussi, donc N_r <- rowSums(agg) reste cohérent avec M_r. Les deux dernières colonnes doivent coïncider.

Raisonnement.

  1. \(M_{\text{inter}}\) est le \(M\) calculé après avoir sommé les unités de chaque zone : on perd la ségrégation qui existe à l’intérieur des zones.
  2. \(M_r\) est le \(M\) calculé sur les seules unités de la zone \(r\).
  3. Les poids sont les parts de population des zones, \(N_r/N\).
  4. L’identité \(M = M_{\text{inter}} + \sum_r (N_r/N)\,M_r\) est exacte pour M (additivité de l’entropie) ; elle ne l’est ni pour D ni pour H.
  5. Conséquence : agréger ne peut que réduire M, et la perte vaut exactement le terme intra. C’est une lecture directe du MAUP.
source("R/segregation.R") tab <- seg_sim_city(U = 12, size = 80, p = 0.4, kappa = 3, seed = seg4$seed) zone <- rep(c("nord", "centre", "sud"), each = 4) agg <- rowsum(tab, zone) M_inter <- seg_M(agg) N_r <- rowSums(agg) M_r <- sapply(split(seq_len(nrow(tab)), zone), function(i) seg_M(tab[i, , drop = FALSE])) M_intra <- sum(N_r / sum(N_r) * M_r) c(inter = M_inter, intra = M_intra, total = M_inter + M_intra, direct = seg_M(tab))

Pièges fréquents.

  • Désaligner les zones : rowsum et split trient par ordre alphabétique ; garde le même ordre pour les poids.
  • Pondérer par le nombre d’unités au lieu de la population.
  • Croire que l’identité vaut pour D : seul M (et les indices de la famille entropique) se décompose ainsi.

Pour aller plus loin. Pour des agrégations successives (12 → 6 → 3 → 1 zones), calcule la part « inter » : tu obtiens une courbe de MAUP, avec ses plateaux et ses sauts.
