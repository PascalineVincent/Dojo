MCO, endogénéité, inférence : démonstrations par simulation

Pour chaque notion : un processus générateur de données connu, donc une vérité à retrouver. C’est la meilleure façon de garder l’intuition des biais en tête. Les graines changent chaque jour.

rng = {
  // Générateur pseudo-aléatoire reproductible : graine = jour + id d'exercice + salt.
  // (Source unique : scripts/test_exercices.R évalue cette même cellule avec Node.)
  const today = new Date().toISOString().slice(0, 10);
  const hash = (s) => {
    let h = 1779033703 ^ s.length;
    for (let i = 0; i < s.length; i++) { h = Math.imul(h ^ s.charCodeAt(i), 3432918353); h = (h << 13) | (h >>> 19); }
    return h >>> 0;
  };
  const mulberry32 = (a) => () => {
    a |= 0; a = (a + 0x6d2b79f5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
  return (id, salt = 0, day = today) => {
    const u = mulberry32(hash(`${day}|${id}|${salt}`));
    const int = (a, b) => a + Math.floor(u() * (b - a + 1));
    const pick = (arr) => arr[Math.floor(u() * arr.length)];
    const normal = () => Math.sqrt(-2 * Math.log(1 - u())) * Math.cos(2 * Math.PI * u());
    return { u, int, pick, normal };
  };
}

MCO à la main : l’algèbre matricielle

Marche 1 sur 4 · Guidé

ols0 = { const g = rng("eco-ols-0", salt); return { seed: g.int(1, 9999), pente: g.pick([0.5, 1, 2, -1]) }; }

Les données suivent y = 1 + x + u. Retrouve les coefficients MCO sans lm(), avec l’algèbre matricielle, puis calcule le R².

Formule : \(\hat\beta = (X'X)^{-1}X'y\) ; équations normales \(X'X\hat\beta = X'y\).

AstuceIndice 1 · par où commencer

Écris le modèle sous forme matricielle \(y = X\beta + u\) où \(X\) contient une colonne de 1 et la colonne de \(x\). Les MCO choisissent \(\beta\) pour que les résidus soient orthogonaux aux colonnes de \(X\).

AstuceIndice 2 · les formules

Équations normales : \(X'X\hat\beta = X'y\), soit solve(crossprod(X), crossprod(X, y)). Résidus : y - X %*% beta. \(R^2 = 1 - \sum e^2 / \sum (y - \bar y)^2\).

Raisonnement.

  1. On minimise la somme des carrés des résidus \(\sum_i e_i^2 = e'e\). La condition du premier ordre est \(X'(y - X\hat\beta) = 0\) : les résidus sont orthogonaux à chaque colonne de \(X\).
  2. Cela donne les équations normales \(X'X\hat\beta = X'y\). solve(crossprod(X), crossprod(X, y)) les résout directement, ce qui est plus stable que d’inverser \(X'X\) puis de multiplier.
  3. Les résidus \(e = y - X\hat\beta\) somment à zéro (parce qu’il y a une constante) et sont orthogonaux à \(x\) : tu peux le vérifier avec sum(e) et sum(e * x).
  4. \(R^2 = 1 - \dfrac{\sum e_i^2}{\sum (y_i - \bar y)^2}\) : la part de la variance de \(y\) expliquée par la régression.
  5. Les résultats coïncident avec lm(y ~ x) à l’arrondi machine près : c’est ce que vérifie la correction.
set.seed(ols0$seed) n <- 100 x <- rnorm(n) y <- 1 + ols0$pente * x + rnorm(n) X <- cbind(1, x) beta <- solve(crossprod(X), crossprod(X, y)) # équations normales X'X b = X'y e <- y - X %*% beta # résidus R2 <- 1 - sum(e^2) / sum((y - mean(y))^2) # part de variance expliquée c(const = beta[1], pente = beta[2], R2 = R2) 
set.seed(ols0$seed)
n <- 100
x <- rnorm(n)
y <- 1 + ols0$pente * x + rnorm(n)
X <- cbind(1, x)
beta <- solve(crossprod(X), crossprod(X, y))          # équations normales X'X b = X'y
e    <- y - X %*% beta                                # résidus
R2   <- 1 - sum(e^2) / sum((y - mean(y))^2)           # part de variance expliquée
c(const = beta[1], pente = beta[2], R2 = R2)

Pièges fréquents.

  • Oublier la colonne de 1 : on estime un modèle sans constante (et le \(R^2\) n’est plus comparable).
  • Écrire X %*% y : il faut crossprod(X, y) ou t(X) %*% y.
  • Calculer le \(R^2\) avec une variance non centrée (sans mean(y)).

Pour aller plus loin. La marche suivante se sert de cette mécanique pour montrer ce qui se passe quand on omet une variable pertinente.

Biais de variable omise

Marche 2 sur 4 · À compléter

ovb1 = { const g = rng("eco-ovb-1", salt); return { seed: g.int(1, 9999), rho: g.pick([0.3, 0.5, 0.7]) }; }

Le vrai modèle est y = 1 + 2x + 3z + u, avec une corrélation de entre x et z. Estime la régression « longue » (avec z) puis la régression « courte » (sans z) et vérifie la formule du biais : coefficient court = coefficient long de x + (coefficient long de z) × δ, où δ est la pente de la régression auxiliaire de z sur x.

AstuceIndice 1 · par où commencer

Trois régressions interviennent : la longue (y sur x et z), la courte (y sur x seulement) et une auxiliaire (z sur x) qui mesure à quel point x et z vont de pair.

AstuceIndice 2 · la formule

coef(lm(y ~ x))["x"] et coef(lm(z ~ x))["x"]. La formule est une identité exacte sur l’échantillon : court et formule doivent être égaux au dernier chiffre.

Raisonnement.

  1. Dans la régression longue, \(\hat\beta_x\) est l’effet de x à z fixé.
  2. Dans la courte, x « récupère » l’effet de z dans la mesure où x et z sont corrélés.
  3. Régression auxiliaire \(z = \delta_0 + \delta\,x + \text{résidu}\) ; en remplaçant dans le modèle long on trouve \(\tilde\beta_x = \hat\beta_x + \hat\beta_z\,\hat\delta\).
  4. C’est une identité algébrique des MCO (pas une approximation) : court et formule coïncident au dernier chiffre.
  5. Dans la simulation, le biais vaut environ \(3\rho\) : positif, car z agit positivement sur y et est positivement corrélé à x. Il disparaît si \(\rho = 0\) ou si z n’agit pas sur y.
set.seed(ovb1$seed) n <- 500 z <- rnorm(n) x <- ovb1$rho * z + sqrt(1 - ovb1$rho^2) * rnorm(n) y <- 1 + 2 * x + 3 * z + rnorm(n) longue <- coef(lm(y ~ x + z)) court <- coef(lm(y ~ x))["x"] delta <- coef(lm(z ~ x))["x"] formule <- unname(longue["x"] + longue["z"] * delta) c(long = unname(longue["x"]), court = unname(court), formule = formule) 
set.seed(ovb1$seed)
n <- 500
z <- rnorm(n)
x <- ovb1$rho * z + sqrt(1 - ovb1$rho^2) * rnorm(n)
y <- 1 + 2 * x + 3 * z + rnorm(n)

longue <- coef(lm(y ~ x + z))
court   <- coef(lm(y ~ x))["x"]
delta   <- coef(lm(z ~ x))["x"]
formule <- unname(longue["x"] + longue["z"] * delta)
c(long = unname(longue["x"]), court = unname(court), formule = formule)

Pièges fréquents.

  • Régresser x sur z pour la régression auxiliaire : on obtient une autre pente (covariance divisée par la variance de z), pas \(\delta\).
  • Croire que le biais disparaît quand \(n\) grandit : c’est un biais de convergence, pas de petit échantillon.
  • Ne regarder que la corrélation entre x et z : le sens du biais est le produit de deux signes, celui de \(\beta_z\) et celui de \(\delta\).

Pour aller plus loin. Mets \(\rho = 0\) puis le coefficient de z à 0 dans la simulation : le biais disparaît dans les deux cas. Le même raisonnement donne l’effet d’une variable de contrôle « mauvaise » (collider) dans l’autre sens.

Erreurs-types robustes (HC1) à la main

Marche 3 sur 4 · À compléter

hc1 = { const g = rng("eco-hc-1", salt); return { seed: g.int(1, 9999) }; }

Ici la variance des erreurs augmente avec |x| (hétéroscédasticité). Calcule l’erreur-type MCO usuelle et l’erreur-type robuste de White (HC1) de la pente, sans sandwich : \(\hat V = \frac{n}{n-k}(X'X)^{-1}\big(\sum_i e_i^2 x_i x_i'\big)(X'X)^{-1}\).

AstuceIndice 1 · par où commencer

Les coefficients MCO ne changent pas : seule la variance estimée change. Repère la forme « sandwich » : deux fois \((X'X)^{-1}\) autour d’un cœur qui contient les résidus au carré.

AstuceIndice 2 · la formule

X * e multiplie chaque ligne de X par le résidu correspondant ; crossprod(X * e) donne alors \(\sum_i e_i^2 x_i x_i'\).

Raisonnement.

  1. \(\hat\beta - \beta = (X'X)^{-1}X'u\), donc \(\mathrm{Var}(\hat\beta) = (X'X)^{-1}X'\,\mathrm{Var}(u)\,X(X'X)^{-1}\).
  2. Sous homoscédasticité, \(\mathrm{Var}(u) = \sigma^2 I\) et la formule se simplifie en \(\sigma^2 (X'X)^{-1}\) : c’est l’erreur-type usuelle.
  3. Sous hétéroscédasticité, on remplace \(\mathrm{Var}(u)\) par la matrice diagonale des \(e_i^2\) : le cœur devient \(\sum_i e_i^2\, x_i x_i'\).
  4. crossprod(X * e) le calcule d’un coup, car X * e multiplie chaque ligne de X par son résidu.
  5. Le facteur \(n/(n-k)\) est la correction de petit échantillon de HC1 (celle de Stata et de sandwich::vcovHC(type = "HC1")).
set.seed(hc1$seed) n <- 200; k <- 2 x <- rnorm(n) y <- 1 + 0.5 * x + (0.5 + abs(x)) * rnorm(n) X <- cbind(1, x) XtXi <- solve(crossprod(X)) beta <- XtXi %*% crossprod(X, y) e <- as.numeric(y - X %*% beta) meat <- crossprod(X * e) V_hc1 <- n / (n - k) * XtXi %*% meat %*% XtXi se_ols <- sqrt(sum(e^2) / (n - k) * XtXi[2, 2]) c(ols = se_ols, hc1 = sqrt(V_hc1[2, 2])) 
set.seed(hc1$seed)
n <- 200; k <- 2
x <- rnorm(n)
y <- 1 + 0.5 * x + (0.5 + abs(x)) * rnorm(n)
X <- cbind(1, x)
XtXi <- solve(crossprod(X))
beta <- XtXi %*% crossprod(X, y)
e <- as.numeric(y - X %*% beta)

meat  <- crossprod(X * e)
V_hc1 <- n / (n - k) * XtXi %*% meat %*% XtXi
se_ols <- sqrt(sum(e^2) / (n - k) * XtXi[2, 2])
c(ols = se_ols, hc1 = sqrt(V_hc1[2, 2]))

Pièges fréquents.

  • Diviser par \(n\) au lieu de \(n-k\) : on obtient HC0.
  • Écrire crossprod(X) * e^2 : la multiplication par \(e\) doit se faire ligne par ligne sur X.
  • Penser que les erreurs-types robustes sont toujours plus grandes : ici l’hétéroscédasticité croît avec \(|x|\) et l’erreur-type usuelle sous-estime ; dans d’autres configurations, c’est l’inverse.

Pour aller plus loin. Compare avec sandwich::vcovHC(lm(y ~ x), type = "HC1") sur ton ordinateur. Pour des données groupées, remplace le cœur par la somme sur les grappes de \((X_g'e_g)(X_g'e_g)'\) : ce sont les erreurs-types clusterisées.

Variables instrumentales : Wald et 2SLS

Marche 4 sur 4 · Autonome

iv1 = { const g = rng("eco-iv-1", salt); return { seed: g.int(1, 9999) }; }

La variable x est endogène : une cause non observée e affecte à la fois x et y. On dispose d’un instrument z. Le vrai effet de x sur y est 2. Compare l’estimateur MCO (biaisé), le 2SLS en deux étapes et l’estimateur de Wald cov(z, y) / cov(z, x) : dans le cas juste-identifié, les deux derniers sont identiques.

AstuceIndice 1 · par où commencer

Deux chemins mènent au même nombre : un rapport de covariances (Wald) et deux régressions emboîtées (2SLS). Pour la première étape, demande-toi quelle variable on régresse sur l’instrument \(z\).

AstuceIndice 2 · la formule

fitted(lm(x ~ z)) pour la première étape, puis coef(lm(y ~ x_hat))["x_hat"]. Attention : les erreurs-types de cette seconde étape « à la main » ne sont pas valides (il faut AER::ivreg ou fixest::feols), mais le coefficient est correct.

Raisonnement.

  1. \(x\) contient une partie corrélée à l’erreur \(e\) (elle est endogène), donc le MCO est biaisé.
  2. L’instrument \(z\) doit être pertinent (corrélé à \(x\)) et exclu (non corrélé à \(e\) : il n’agit sur \(y\) qu’à travers \(x\)).
  3. Première étape : \(\hat x = \hat\pi_0 + \hat\pi z\) extrait la part de \(x\) qui ne dépend que de \(z\), donc exogène.
  4. Seconde étape : régresser \(y\) sur \(\hat x\) donne \(\hat\beta_{IV}\).
  5. Dans le cas juste-identifié, \(\hat\beta_{IV} = \mathrm{cov}(z,y)/\mathrm{cov}(z,x)\) : c’est la forme de Wald, le rapport entre la « forme réduite » et la « première étape ».
set.seed(iv1$seed) n <- 1000 z <- rnorm(n); e <- rnorm(n) x <- 0.8 * z + 0.8 * e + rnorm(n) y <- 1 + 2 * x + e mco <- coef(lm(y ~ x))["x"] x_hat <- fitted(lm(x ~ z)) iv <- coef(lm(y ~ x_hat))["x_hat"] wald <- cov(z, y) / cov(z, x) c(mco = unname(mco), iv = unname(iv), wald = wald) 
set.seed(iv1$seed)
n <- 1000
z <- rnorm(n); e <- rnorm(n)
x <- 0.8 * z + 0.8 * e + rnorm(n)
y <- 1 + 2 * x + e

mco   <- coef(lm(y ~ x))["x"]
x_hat <- fitted(lm(x ~ z))
iv    <- coef(lm(y ~ x_hat))["x_hat"]
wald  <- cov(z, y) / cov(z, x)
c(mco = unname(mco), iv = unname(iv), wald = wald)

Pièges fréquents.

  • Régresser \(y\) sur \(x\) à la seconde étape : on retombe sur le MCO.
  • Se fier aux erreurs-types de lm(y ~ x_hat) : elles sont fausses (x_hat est estimé) ; utilise AER::ivreg(y ~ x | z).
  • Ne pas vérifier la pertinence : avec un instrument faible, le rapport est instable et le biais tend vers celui du MCO.

Pour aller plus loin. Réduis le coefficient de \(z\) dans la première étape (0,8 puis 0,05) et regarde la dispersion de l’estimateur VI sur 500 simulations : c’est le problème des instruments faibles.
