Statistiques (L1)

Probabilités, estimation, tests : rappels et simulation

Rappels de L1 par la simulation : on ne se contente pas de la formule, on la vérifie. Les énoncés changent chaque jour (graine = date). Trois pistes : estimation et simulation, statistiques descriptives (résumer, comparer des groupes, repérer les valeurs atypiques) et comparaisons et tests (Welch, khi-deux, permutation, comparaisons multiples). Une section d’aide R (réflexes, erreurs fréquentes) et une boîte à outils « quelle méthode, quelle fonction ? » terminent la page ; chaque exercice a trois indices (orientation, formule, fonction R sur un exemple).

rng = {
  // Générateur pseudo-aléatoire reproductible : graine = jour + id d'exercice + salt.
  // (Source unique : scripts/test_exercices.R évalue cette même cellule avec Node.)
  const today = new Date().toISOString().slice(0, 10);
  const hash = (s) => {
    let h = 1779033703 ^ s.length;
    for (let i = 0; i < s.length; i++) { h = Math.imul(h ^ s.charCodeAt(i), 3432918353); h = (h << 13) | (h >>> 19); }
    return h >>> 0;
  };
  const mulberry32 = (a) => () => {
    a |= 0; a = (a + 0x6d2b79f5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
  return (id, salt = 0, day = today) => {
    const u = mulberry32(hash(`${day}|${id}|${salt}`));
    const int = (a, b) => a + Math.floor(u() * (b - a + 1));
    const pick = (arr) => arr[Math.floor(u() * arr.length)];
    const normal = () => Math.sqrt(-2 * Math.log(1 - u())) * Math.cos(2 * Math.PI * u());
    return { u, int, pick, normal };
  };
}

TCL par simulation

Marche 1 sur 3 · Guidé

tcl1 = { const g = rng("stats-tcl-1", salt); return { n: g.pick([10, 25, 50, 100]), m: g.pick([2, 5, 10]) }; }

On tire n = observations indépendantes d’une loi exponentielle d’espérance (son écart-type vaut aussi ). Simule 2 000 moyennes empiriques et compare leur écart-type à la valeur théorique σ/√n.

AstuceIndice 1 · par où commencer

Deux ingrédients : (i) simuler un grand nombre de moyennes de \(n\) observations ; (ii) écrire ce que la théorie annonce pour l’écart-type d’une moyenne. Tu compares ensuite les deux.

AstuceIndice 2 · la formule

Une loi exponentielle d’espérance \(m\) a pour paramètre rate = 1/m dans rexp(). Pour des observations i.i.d., \(\mathrm{sd}(\bar X) = \sigma / \sqrt{n}\).

AstuceIndice 3 · la fonction R, sur un exemple

replicate(B, expr) répète expr B fois et renvoie le vecteur des résultats ; sd() donne ensuite la dispersion de ces B moyennes. Exemple (autre loi, autre taille) :

x <- replicate(1000, mean(runif(10)))   # 1000 moyennes de 10 tirages uniformes
sd(x)                                   # dispersion simulée
# la théorie : sigma / sqrt(n), ici sigma = sqrt(1/12) pour une uniforme(0, 1)
sqrt(1/12) / sqrt(10)

Raisonnement.

  1. Une observation exponentielle d’espérance \(m\) a pour variance \(m^2\) : son écart-type est \(m\) (propriété de la loi exponentielle).
  2. Pour la moyenne de \(n\) observations indépendantes, \(\mathrm{Var}(\bar X) = \sigma^2/n\), donc \(\mathrm{sd}(\bar X) = m/\sqrt{n}\).
  3. On répète 2 000 fois l’expérience « tirer \(n\) valeurs, en faire la moyenne » avec replicate. L’écart-type de ces 2 000 moyennes doit approcher \(m/\sqrt{n}\) ; la précision de la simulation est d’environ \(1/\sqrt{2\times 2000} \approx 1{,}6\ \%\) en valeur relative.
  4. Le TCL dit en plus que la forme devient gaussienne : trace hist(moyennes) pour \(n\) grand.
n <- tcl1$n; m <- tcl1$m set.seed(42) moyennes <- replicate(2000, mean(rexp(n, rate = 1 / m))) c(simule = sd(moyennes), theorie = m / sqrt(n)) 
n <- tcl1$n; m <- tcl1$m
set.seed(42)
moyennes <- replicate(2000, mean(rexp(n, rate = 1 / m)))
c(simule = sd(moyennes), theorie = m / sqrt(n))

Pièges fréquents.

  • rexp(n, m) : le second argument est le taux \(1/m\), pas la moyenne.
  • Écrire mean(rexp(n, ...)) hors de replicate : on obtient 2 000 fois la même valeur.
  • Confondre l’écart-type des observations (\(m\)) et celui de la moyenne (\(m/\sqrt n\)).

Pour aller plus loin. Compare l’asymétrie des moyennes pour \(n = 5\) puis \(n = 100\) : le TCL est asymptotique, et la loi exponentielle est très asymétrique. La marche suivante construit un intervalle de confiance.

Intervalle de confiance d’une moyenne

Marche 2 sur 3 · À compléter

ic1 = {
  const g = rng("stats-ic-1", salt);
  const mu = g.int(50, 120), sd = g.int(5, 20), n = g.int(12, 30);
  return { x: Array.from({ length: n }, () => Math.round((mu + sd * g.normal()) * 10) / 10) };
}

Un échantillon de mesures est tiré d’une loi supposée normale (inconnue). Calcule l’intervalle de confiance à 95 % de la moyenne avec le quantile de Student adapté au petit échantillon.

AstuceIndice 1 · par où commencer

Un IC s’écrit « estimation ± marge ». Ici \(\sigma\) est inconnu et l’échantillon petit : quelle loi gouverne le rapport \((\bar x - \mu)/(s/\sqrt n)\) ?

AstuceIndice 2 · la formule

Pour un IC bilatéral à 95 %, on prend le quantile d’ordre 0,975 de la loi de Student à \(n-1\) degrés de liberté : qt(0.975, df = n - 1). Vérifie avec t.test(x)$conf.int.

AstuceIndice 3 · la fonction R, sur un exemple

qt(p, df) renvoie le quantile de la loi de Student. Pour un IC à 95 %, on veut le quantile 0,975 (2,5 % de chaque côté). Exemple sur 4 valeurs :

y <- c(4, 6, 5, 7); n <- length(y)
qt(0.975, df = n - 1)                                    # valeur critique
mean(y) + c(-1, 1) * qt(0.975, n - 1) * sd(y) / sqrt(n) # borne basse, borne haute
# vérification : t.test(y)$conf.int

Raisonnement.

  1. Si les données sont normales, \((\bar X - \mu)/(S/\sqrt n)\) suit une loi de Student à \(n-1\) degrés de liberté.
  2. L’IC à 95 % est donc \(\bar x \pm t_{n-1,\,0.975}\; s/\sqrt n\).
  3. Le quantile de Student est supérieur à 1,96 (par exemple 2,26 pour \(n = 10\)) : il traduit l’incertitude supplémentaire due à l’estimation de \(\sigma\) par \(s\).
  4. t.test(x)$conf.int donne le même intervalle : c’est la vérification utilisée par la correction.
x <- as.numeric(unlist(ic1$x)) n <- length(x); m <- mean(x); s <- sd(x) marge <- qt(0.975, df = n - 1) * s / sqrt(n) c(inf = m - marge, sup = m + marge) 
x <- as.numeric(unlist(ic1$x))
n <- length(x); m <- mean(x); s <- sd(x)
marge <- qt(0.975, df = n - 1) * s / sqrt(n)
c(inf = m - marge, sup = m + marge)

Pièges fréquents.

  • Utiliser 1,96 avec un petit échantillon : l’IC est trop étroit et sa couverture réelle est inférieure à 95 %.
  • Écrire sd(x) / n au lieu de sd(x) / sqrt(n).
  • Lire « 95 % de chances que \(\mu\) soit dans cet intervalle » : la probabilité porte sur la procédure (sur de nombreux échantillons), pas sur l’intervalle calculé.

Pour aller plus loin. La marche suivante mesure justement la couverture réelle de cet intervalle par simulation, avec Student et avec 1,96.

Couverture réelle de l’intervalle de confiance

Marche 3 sur 3 · Autonome

couv1 = { const g = rng("stats-couv-1", salt); return { n: g.pick([4, 5, 6, 8, 10]) }; }

On observe des échantillons normaux de n = observations (vraie moyenne 100, écart-type 15). On construit l’IC à 95 % de deux façons : avec le quantile de Student, puis avec la valeur 1,96. Sur 4 000 échantillons simulés, dans quelle proportion l’IC contient-il vraiment la vraie moyenne ?

AstuceIndice 1 · par où commencer

Pour chaque échantillon simulé, deux choses : la demi-largeur de l’intervalle (la marge), puis un test vrai/faux « l’intervalle contient-il \(\mu\) ? ». La moyenne de ces vrai/faux est la couverture.

AstuceIndice 2 · la formule

marge = crit * sd(x) / sqrt(n) ; l’IC contient \(\mu\) si abs(mean(x) - mu) <= marge. Pour Student la couverture doit être proche de 0,95.

AstuceIndice 3 · la fonction R, sur un exemple

Dans replicate(B, { ... }), la dernière expression du bloc est la valeur renvoyée. Un test logique donne TRUE/FALSE, et mean() d’un vecteur logique est la proportion de TRUE. Exemple :

mean(replicate(2000, {
  z <- rnorm(5)                      # un échantillon
  abs(mean(z)) < 1                   # TRUE si la moyenne est à moins de 1 de 0
}))
# pour l'IC : abs(mean(x) - mu) < marge, avec marge = crit * sd(x) / sqrt(n)

Raisonnement.

  1. « IC à 95 % » est une promesse sur la procédure : sur de nombreux échantillons, 95 % des intervalles doivent contenir la vraie moyenne. La simulation permet de le vérifier parce qu’on connaît \(\mu\).
  2. Pour chaque échantillon on calcule la marge crit * sd(x) / sqrt(n) puis on teste \(|\bar x - \mu| \le\) marge.
  3. Avec le quantile de Student \(t_{n-1,\,0.975}\), la couverture est proche de 95 %.
  4. Avec 1,96, la couverture est nettement plus basse (environ 88 % pour \(n = 5\)) : on ne tient pas compte de l’incertitude sur \(\sigma\) (estimé par \(s\)).
  5. set.seed(1) à l’intérieur de la fonction impose les mêmes échantillons aux deux calculs : la comparaison se fait « à données égales ». La précision de la simulation est d’environ \(\sqrt{0{,}95 \times 0{,}05/4000} \approx 0{,}35\) point.
mu <- 100; sigma <- 15; n <- couv1$n couverture <- function(crit, B = 4000) { set.seed(1) mean(replicate(B, { x <- rnorm(n, mu, sigma) marge <- crit * sd(x) / sqrt(n) # sd(x), pas sigma : sigma est inconnu en pratique abs(mean(x) - mu) <= marge # l'IC [mean(x) - marge ; mean(x) + marge] contient mu })) } c(student = couverture(qt(0.975, n - 1)), normale = couverture(1.96)) 
mu <- 100; sigma <- 15; n <- couv1$n
couverture <- function(crit, B = 4000) {
  set.seed(1)
  mean(replicate(B, {
    x <- rnorm(n, mu, sigma)
    marge <- crit * sd(x) / sqrt(n)             # sd(x), pas sigma : sigma est inconnu en pratique
    abs(mean(x) - mu) <= marge                  # l'IC [mean(x) - marge ; mean(x) + marge] contient mu
  }))
}
c(student = couverture(qt(0.975, n - 1)), normale = couverture(1.96))

Pièges fréquents.

  • Utiliser sigma (inconnu en pratique) à la place de sd(x) : l’IC serait trop précis, et l’on perdrait précisément ce que la loi de Student corrige.
  • Mettre set.seed() à l’intérieur de replicate : tous les échantillons seraient identiques.
  • Lire 93,6 % comme une « erreur » : avec 4 000 tirages, l’aléa de simulation est d’environ 0,35 point.

Pour aller plus loin. Refais avec \(n = 30\) puis \(n = 200\) : les deux colonnes se rejoignent, c’est la convergence de la loi de Student vers la loi normale.

Résumer une série : position, dispersion, forme

Marche 1 sur 3 · Guidé

desc1 = { const g = rng("stats-desc-1", salt); return { seed: g.int(1, 9999), n: g.pick([30, 40, 50]) }; }

Les revenus mensuels (en euros) de ménages sont simulés avec une loi lognormale, très asymétrique comme les vrais revenus. Calcule la moyenne, la médiane, l’écart-type, l’écart interquartile et le coefficient d’asymétrie (skewness).

AstuceIndice 1 · par où commencer

Il y a trois familles de résumés : la position (autour de quoi se situent les valeurs), la dispersion (à quel point elles s’étalent) et la forme (symétrique ou étirée d’un côté). Pour chacune, R a une fonction toute prête, sauf l’asymétrie.

AstuceIndice 2 · les fonctions

mean(x), median(x), sd(x), IQR(x) (ou diff(quantile(x, c(0.25, 0.75)))). Asymétrie : mean(((x - mean(x)) / sd(x))^3).

AstuceIndice 3 · la fonction R, sur un exemple

quantile(x, c(0.25, 0.75)) renvoie un vecteur nommé ; unname() retire les noms pour obtenir un nombre propre. L’asymétrie se calcule avec mean() d’un vecteur. Exemple :

y <- c(2, 3, 3, 4, 10)
q <- quantile(y, c(0.25, 0.75))
unname(q[2] - q[1])                      # écart interquartile (ou IQR(y))
mean(((y - mean(y)) / sd(y))^3)          # asymétrie : positive si queue à droite

Raisonnement.

  1. Position : la moyenne est tirée par les valeurs extrêmes, la médiane (valeur qui coupe l’échantillon en deux) non. Pour une distribution étirée à droite, comme les revenus, on a moyenne \(>\) médiane : l’écart entre les deux est déjà un signal d’asymétrie.
  2. Dispersion : l’écart-type \(s = \sqrt{\sum (x_i - \bar x)^2/(n-1)}\) est sensible aux extrêmes. L’écart interquartile \(Q_3 - Q_1\) décrit la largeur des 50 % centraux : il est robuste.
  3. Forme : le moment d’ordre 3 standardisé, \(\overline{((x - \bar x)/s)^3}\), est positif quand la queue de droite est plus longue, négatif sinon, proche de 0 pour une distribution symétrique.
  4. Pour résumer honnêtement une variable de revenu, on donne la médiane et l’écart interquartile (ou les déciles), et la moyenne en complément.
set.seed(desc1$seed) x <- round(rlnorm(desc1$n, meanlog = 7.4, sdlog = 0.6)) moy <- mean(x) med <- median(x) sdx <- sd(x) iqr <- IQR(x) # = diff(quantile(x, c(0.25, 0.75))) asym <- mean(((x - mean(x)) / sd(x))^3) c(moyenne = moy, mediane = med, ecart_type = sdx, iqr = iqr, asymetrie = asym) 
set.seed(desc1$seed)
x <- round(rlnorm(desc1$n, meanlog = 7.4, sdlog = 0.6))
moy  <- mean(x)
med  <- median(x)
sdx  <- sd(x)
iqr  <- IQR(x)                                   # = diff(quantile(x, c(0.25, 0.75)))
asym <- mean(((x - mean(x)) / sd(x))^3)
c(moyenne = moy, mediane = med, ecart_type = sdx, iqr = iqr, asymetrie = asym)

Pièges fréquents.

  • sd() divise par \(n-1\) (estimateur sans biais de \(\sigma\)), pas par \(n\) : les résultats diffèrent de ceux d’une formule « à la main » avec mean((x - mean(x))^2).
  • Il existe plusieurs définitions de l’asymétrie (avec ou sans correction de petit échantillon : e1071::skewness types 1, 2, 3) et neuf définitions des quantiles ; R utilise le type 7 par défaut, Stata ou SAS d’autres. Précise toujours laquelle tu utilises.
  • Décrire une variable très asymétrique par « moyenne \(\pm\) écart-type » : la moyenne moins un écart-type peut devenir négative alors que la variable est strictement positive.

Pour aller plus loin. Passe les revenus au logarithme (log(x)) et recalcule l’asymétrie : elle devient proche de 0. C’est la raison pour laquelle on travaille souvent avec des revenus en logarithme.

Tableau descriptif par groupe

Marche 2 sur 3 · À compléter

desc2 = { const g = rng("stats-desc-2", salt); return { seed: g.int(1, 9999) }; }

Un échantillon de 300 salariés (salaire horaire en euros) est réparti en trois niveaux de diplôme. Construis le tableau descriptif par groupe : effectif, moyenne, médiane et écart-type du salaire pour chaque diplôme, puis la part de chaque groupe dans l’échantillon.

AstuceIndice 1 · par où commencer

Résumer par groupe, c’est calculer la même statistique sur chaque sous-échantillon. Un seul outil (tapply) suffit pour les quatre premières lignes du tableau ; la part se déduit de l’effectif.

AstuceIndice 2 · les fonctions

table(diplome) ou tapply(salaire, diplome, length) ; tapply(salaire, diplome, mean) ; avec median puis sd. La part est effectif / sum(effectif).

AstuceIndice 3 · la fonction R, sur un exemple

tapply(valeurs, groupes, fonction) calcule la fonction pour chaque modalité du facteur et renvoie un vecteur nommé. Exemple :

v <- c(10, 12, 20, 22, 30)
g <- c("a", "a", "b", "b", "b")
tapply(v, g, mean)       # a: 11, b: 24
tapply(v, g, length)     # effectifs par groupe
tapply(v, g, sd)         # écart-type par groupe

Raisonnement.

  1. La logique est « découper, appliquer, recombiner » (split-apply-combine). tapply(salaire, diplome, mean) découpe salaire selon diplome, applique mean à chaque morceau et recompose le résultat.
  2. Les groupes sont rangés dans l’ordre alphabétique (Bac, Licence, Master), pas dans l’ordre d’apparition : c’est important pour aligner plusieurs tableaux.
  3. Compare moyenne et médiane dans chaque groupe : l’écart dit où se concentre l’asymétrie.
  4. Affiche toujours l’effectif à côté des moyennes : un écart-type calculé sur 5 observations n’a pas de valeur, et la part dans l’échantillon renseigne sur la représentativité.
  5. Équivalents : aggregate(salaire ~ diplome, FUN = mean), dplyr::group_by() |> summarise(), et pour des tableaux publiables gtsummary::tbl_summary() ou modelsummary::datasummary() (à utiliser en local).
set.seed(desc2$seed) n <- 300 diplome <- sample(c("Bac", "Licence", "Master"), n, replace = TRUE, prob = c(0.5, 0.3, 0.2)) base <- c(Bac = 12, Licence = 15, Master = 19)[diplome] salaire <- round(base * exp(rnorm(n, 0, 0.25)), 2) effectif <- table(diplome) # ou tapply(salaire, diplome, length) moyenne <- tapply(salaire, diplome, mean) mediane <- tapply(salaire, diplome, median) ecart <- tapply(salaire, diplome, sd) tableau <- rbind(effectif = effectif, moyenne = moyenne, mediane = mediane, ecart_type = ecart, part = effectif / sum(effectif)) round(tableau, 3)

Pièges fréquents.

  • Valeurs manquantes : sans na.rm = TRUE, une seule NA rend toute la moyenne de son groupe NA.
  • Confondre la part du groupe dans l’échantillon (effectif / sum(effectif)) et sa part dans la masse salariale (tapply(salaire, diplome, sum) / sum(salaire)).
  • Un groupe sans observation donne NA avec tapply : définis le facteur avec ses levels complets si tu veux conserver la colonne.

Pour aller plus loin. Ajoute une ligne « écart à la moyenne générale » (moyenne - mean(salaire)) puis une moyenne pondérée avec des poids de sondage (weighted.mean). La marche suivante apprend à repérer les valeurs atypiques.

Repérer les valeurs atypiques

Marche 3 sur 3 · Autonome

desc3 = { const g = rng("stats-desc-3", salt); return { seed: g.int(1, 9999), k: g.pick([1.5, 3]) }; }

Une série de 200 valeurs contient une dizaine de valeurs très élevées. Écris atypiques(x, k) qui renvoie les positions des valeurs hors des « clôtures » de Tukey (de Q1 − k × IQR à Q3 + k × IQR) avec k = , compare avec la règle des 3 écarts-types, et mesure l’effet du retrait sur la moyenne et la médiane.

AstuceIndice 1 · par où commencer

Une valeur est « atypique » si elle sort d’un intervalle construit à partir de la distribution du cœur des données. Les quartiles décrivent ce cœur ; l’écart interquartile en donne la largeur.

AstuceIndice 2 · les clôtures

Clôture basse : \(Q_1 - k\,\mathrm{IQR}\) ; clôture haute : \(Q_3 + k\,\mathrm{IQR}\). En R : which(x < q[1] - k * IQR(x) | x > q[2] + k * IQR(x)).

AstuceIndice 3 · la fonction R, sur un exemple

which(condition) renvoie les positions où la condition est vraie ; | signifie « ou ». Pour les seuils de Tukey, utilise les deux quartiles et l’IQR. Exemple :

y <- c(1, 2, 2, 3, 3, 4, 40)
q <- quantile(y, c(0.25, 0.75)); iqr <- q[2] - q[1]
which(y < q[1] - 1.5 * iqr | y > q[2] + 1.5 * iqr)   # position 7

Raisonnement.

  1. La règle de Tukey s’appuie sur des statistiques robustes (les quartiles) : les valeurs atypiques n’influencent presque pas leurs propres seuils. \(k = 1{,}5\) désigne les valeurs « atypiques », \(k = 3\) les valeurs « très atypiques ».
  2. La règle des 3 écarts-types utilise la moyenne et l’écart-type, que les valeurs atypiques tirent vers elles : le seuil monte et les valeurs extrêmes se masquent entre elles (masking). Elle en détecte donc moins.
  3. Retirer les valeurs détectées déplace nettement la moyenne mais à peine la médiane : c’est la définition de la robustesse.
  4. Détecter n’est pas supprimer. Une valeur atypique peut être une erreur de saisie, mais aussi une vraie observation, souvent la plus intéressante (hauts revenus, ville très ségréguée). On documente, on teste la sensibilité des résultats, on ne supprime pas en silence.
set.seed(desc3$seed) x <- c(rnorm(190, 50, 8), rnorm(10, 110, 15)) k <- desc3$k atypiques <- function(x, k) { q <- quantile(x, c(0.25, 0.75)) which(x < q[1] - k * IQR(x) | x > q[2] + k * IQR(x)) } t_idx <- atypiques(x, k) z_idx <- which(abs(x - mean(x)) / sd(x) > 3) sans <- x[setdiff(seq_along(x), t_idx)] c(n_tukey = length(t_idx), n_z3 = length(z_idx), moy_avant = mean(x), moy_apres = mean(sans), med_avant = median(x), med_apres = median(sans))

Test t de Welch à la main

Marche 1 sur 4 · Guidé

tt1 = { const g = rng("stats-t-1", salt); return { seed: g.int(1, 9999), n1: g.pick([15, 20, 30]), n2: g.pick([20, 25, 40]), delta: g.pick([0, 2, 4]) }; }

Deux groupes d’élèves passent le même test. Le groupe A compte élèves, le groupe B en compte . Teste l’égalité des moyennes avec le test t de Welch (les variances ne sont pas supposées égales), puis calcule la taille d’effet de Cohen.

AstuceIndice 1 · par où commencer

Sous H0 (moyennes égales), la différence \(m_1 - m_2\) est centrée sur 0. Il faut la comparer à sa variabilité d’échantillonnage : l’erreur-type. Pour une différence de deux moyennes indépendantes, les variances des deux moyennes s’additionnent.

AstuceIndice 2 · les formules

se = sqrt(v1/n1 + v2/n2) ; t = (m1 - m2) / se ; p = 2 * pt(-abs(t), df) ; écart-type poolé : sqrt(((n1 - 1) * v1 + (n2 - 1) * v2) / (n1 + n2 - 2)).

AstuceIndice 3 · la fonction R, sur un exemple

Les variances des deux moyennes s’additionnent sous la racine. La p-value bilatérale double la probabilité d’une queue, via pt() sur la valeur absolue de t. Exemple :

v1 <- 4; n1 <- 10; v2 <- 9; n2 <- 15
se <- sqrt(v1 / n1 + v2 / n2)       # erreur-type de la différence
pt(-abs(2.1), df = 18) * 2          # p bilatérale pour t = 2.1
# vérification globale : t.test(a, b) est un test de Welch par défaut

Raisonnement.

  1. H0 : \(\mu_A = \mu_B\). La différence observée \(m_1 - m_2\) a pour variance estimée \(s_1^2/n_1 + s_2^2/n_2\) : les variances de deux moyennes indépendantes s’additionnent, d’où l’erreur-type \(\sqrt{s_1^2/n_1 + s_2^2/n_2}\).
  2. Statistique : \(t = (m_1 - m_2)/\mathrm{se}\), un écart exprimé en erreurs-types.
  3. Welch n’impose pas des variances égales ; la loi de \(t\) est approchée par une Student dont le nombre de degrés de liberté (non entier) est donné par la formule de Welch-Satterthwaite. C’est le test par défaut de t.test() en R, et celui à utiliser par défaut.
  4. \(p = 2\,P(T_{\mathrm{df}} < -|t|)\) : test bilatéral, on compte les deux queues.
  5. Le \(d\) de Cohen exprime la différence en écarts-types poolés, indépendamment de \(n\). La p-value dépend de la taille d’échantillon (avec assez d’observations, tout écart est « significatif »), le \(d\) non : significatif ne veut pas dire important. Repères indicatifs : 0,2 petit, 0,5 moyen, 0,8 grand.
set.seed(tt1$seed) a <- rnorm(tt1$n1, mean = 10 + tt1$delta, sd = 3) b <- rnorm(tt1$n2, mean = 10, sd = 5) m1 <- mean(a); m2 <- mean(b); v1 <- var(a); v2 <- var(b); n1 <- length(a); n2 <- length(b) se <- sqrt(v1 / n1 + v2 / n2) t <- (m1 - m2) / se df <- (v1 / n1 + v2 / n2)^2 / ((v1 / n1)^2 / (n1 - 1) + (v2 / n2)^2 / (n2 - 1)) p <- 2 * pt(-abs(t), df) # bilatéral sp <- sqrt(((n1 - 1) * v1 + (n2 - 1) * v2) / (n1 + n2 - 2)) # écart-type poolé d <- (m1 - m2) / sp c(t = t, df = df, p = p, d = d)

d  <- (m1 - m2) / sp

Pièges fréquents.

  • pt(t, df) sans abs ni facteur 2 : c’est une p-value unilatérale (et fausse si \(t > 0\)).
  • Mettre v1 / n1 sous la racine sans les diviser par \(n\) : c’est l’écart-type des observations, pas l’erreur-type de la moyenne.
  • Lire \(p > 0{,}05\) comme « les moyennes sont égales » : on n’a pas de preuve suffisante d’une différence, ce qui n’est pas la preuve d’une égalité.
  • Tester d’abord l’égalité des variances pour choisir entre Student et Welch : cette procédure en deux temps dégrade les propriétés du test final. Welch d’emblée.

Pour aller plus loin. Mets delta = 0 et répète l’expérience 1 000 fois avec replicate : environ 5 % des p-values sont inférieures à 0,05, c’est la définition du seuil. Compare ensuite avec t.test(a, b).

Test du khi-deux d’indépendance

Marche 2 sur 4 · À compléter

chi1 = { const g = rng("stats-chi2-1", salt); return { seed: g.int(1, 9999), effet: g.pick([0, 0.05, 0.1]) }; }

On croise le niveau de diplôme (Bac, Licence, Master) et la situation d’emploi de 400 personnes. Teste l’indépendance des deux variables : calcule les effectifs attendus sous H0, la statistique du khi-deux, ses degrés de liberté et la p-value.

AstuceIndice 1 · par où commencer

Si le diplôme et la situation d’emploi étaient indépendants, la proportion de personnes en emploi serait la même dans chaque ligne du tableau. Calcule d’abord ce tableau-là (les effectifs attendus) puis mesure son écart au tableau observé.

AstuceIndice 2 · les formules

outer(rowSums(tab), colSums(tab)) / sum(tab) ; sum((tab - attendus)^2 / attendus) ; (nrow(tab) - 1) * (ncol(tab) - 1) ; pchisq(chi2, ddl, lower.tail = FALSE).

AstuceIndice 3 · la fonction R, sur un exemple

Le tableau des effectifs attendus s’obtient avec outer() (produit croisé des totaux). La p-value est la probabilité de dépasser la statistique : lower.tail = FALSE. Exemple :

tab <- matrix(c(20, 30, 25, 25), 2)
attendus <- outer(rowSums(tab), colSums(tab)) / sum(tab)
stat <- sum((tab - attendus)^2 / attendus)
pchisq(stat, df = 1, lower.tail = FALSE)
# vérification : chisq.test(tab, correct = FALSE)

Raisonnement.

  1. Indépendance : \(P(i,j) = P(i)\,P(j)\). Les effectifs attendus sont donc \(E_{ij} = (\text{total ligne}_i \times \text{total colonne}_j)/N\) : outer() fait tous les produits d’un coup.
  2. \(\chi^2 = \sum_{ij} (O_{ij} - E_{ij})^2/E_{ij}\) mesure l’écart entre observé et attendu, normalisé par l’attendu (un écart de 5 pèse plus quand on attend 10 que quand on attend 1 000).
  3. Sous H0, \(\chi^2\) suit approximativement une loi du khi-deux à \((l-1)(c-1)\) degrés de liberté ; l’approximation est bonne si tous les effectifs attendus dépassent environ 5.
  4. La p-value est la queue droite : seules les grandes valeurs signalent un écart.
  5. Un khi-deux significatif dit qu’il y a association, pas qu’elle est forte. Pour la force, on calcule le V de Cramér, \(\sqrt{\chi^2/(N\min(l-1,\,c-1))}\) ; pour savoir où est l’écart, les résidus de Pearson \((O-E)/\sqrt{E}\).
set.seed(chi1$seed) n <- 400 diplome <- sample(c("Bac", "Licence", "Master"), n, replace = TRUE, prob = c(0.5, 0.3, 0.2)) p_emploi <- c(Bac = 0.75, Licence = 0.75 + chi1$effet, Master = 0.75 + 2 * chi1$effet)[diplome] statut <- ifelse(rbinom(n, 1, p_emploi) == 1, "Emploi", "Chômage") tab <- table(diplome, statut) attendus <- outer(rowSums(tab), colSums(tab)) / sum(tab) chi2 <- sum((tab - attendus)^2 / attendus) ddl <- (nrow(tab) - 1) * (ncol(tab) - 1) p <- pchisq(chi2, ddl, lower.tail = FALSE) c(chi2 = chi2, ddl = ddl, p = p)

Pièges fréquents.

  • pchisq(chi2, ddl) sans lower.tail = FALSE donne \(1 - p\) : une p-value de 0,98 devient 0,02.

  • Travailler sur des pourcentages au lieu d’effectifs : le \(\chi^2\) dépend de \(N\) (à pourcentages égaux, un échantillon dix fois plus grand donne un \(\chi^2\) dix fois plus grand).
  • Effectifs attendus inférieurs à 5 dans plusieurs cellules : l’approximation est mauvaise ; utilise fisher.test() ou chisq.test(tab, simulate.p.value = TRUE).

Pour aller plus loin. Compare avec chisq.test(tab), puis calcule le V de Cramér et les résidus de Pearson (tab - attendus) / sqrt(attendus) pour voir quelle cellule s’écarte le plus de l’indépendance.

Test de permutation

Marche 3 sur 4 · Autonome

perm1 = { const g = rng("stats-perm-1", salt); return { seed: g.int(1, 9999), delta: g.pick([0, 0.4, 0.8]) }; }

Deux groupes de 12 observations, très asymétriques (loi lognormale) : l’hypothèse de normalité du test t est douteuse. Écris un test de permutation de la différence de moyennes (4 000 permutations) et compare sa p-value à celle du test t de Welch.

AstuceIndice 1 · par où commencer

Si le groupe n’a aucun effet, l’étiquette A/B de chaque observation est interchangeable. Mélanger les étiquettes au hasard fabrique donc des données « comme sous H0 ». Reste à voir où se situe la différence observée dans cette distribution fabriquée.

AstuceIndice 2 · les formules

g <- sample(groupe) mélange les étiquettes. p-value : (1 + sum(abs(stat) >= abs(obs))) / (B + 1).

AstuceIndice 3 · la fonction R, sur un exemple

sample(groupe) mélange les étiquettes sans les changer de nature (tirage sans remise de tout le vecteur). Compter combien de fois la statistique simulée dépasse l’observée : sum(abs(stat) >= abs(obs)). Exemple :

groupe <- rep(c("A", "B"), each = 3)
sample(groupe)                                  # étiquettes permutées
stat <- c(0.5, -2, 1.5, 3)                      # statistiques simulées
(1 + sum(abs(stat) >= abs(2))) / (length(stat) + 1)

Raisonnement.

  1. Sous H0 (pas d’effet du groupe), toutes les façons de répartir les 24 valeurs entre A et B sont également plausibles. sample(groupe) en tire une au hasard ; on recalcule à chaque fois la statistique d’intérêt. On obtient ainsi sa distribution sous H0, sans supposer la normalité.
  2. La p-value est la proportion de permutations dont la statistique est aussi extrême que celle observée (en valeur absolue pour un test bilatéral).
  3. Le « +1 » au numérateur et au dénominateur compte la répartition observée elle-même, qui est aussi une permutation possible : la p-value ne vaut jamais exactement 0 (minimum \(1/(B+1)\)).
  4. La précision de la simulation est d’environ \(\sqrt{p(1-p)/B}\) : pour \(p = 0{,}05\) et \(B = 4\,000\), environ 0,3 point.
  5. Résultat : proche du Welch quand les données ne sont pas trop extrêmes ; elle s’en écarte avec des queues épaisses. Un test de permutation s’adapte à n’importe quelle statistique (médiane, Gini, indice de ségrégation), alors que le test t est réservé à la moyenne.
set.seed(perm1$seed) a <- round(rlnorm(12, meanlog = 3 + perm1$delta, sdlog = 0.8), 1) b <- round(rlnorm(12, meanlog = 3, sdlog = 0.8), 1) x <- c(a, b); groupe <- rep(c("A", "B"), each = 12) obs <- mean(a) - mean(b) perm_p <- function(x, groupe, obs, B = 4000) { set.seed(1) stat <- replicate(B, { g <- sample(groupe) # étiquettes permutées mean(x[g == "A"]) - mean(x[g == "B"]) }) (1 + sum(abs(stat) >= abs(obs))) / (B + 1) } c(obs = obs, p_perm = perm_p(x, groupe, obs), p_welch = t.test(a, b)$p.value)

Pièges fréquents.

  • Oublier abs : on obtient une p-value unilatérale.
  • Omettre le « +1 » : la p-value peut valoir 0, ce qui n’a pas de sens avec un nombre fini de permutations.
  • Placer set.seed() à l’intérieur de replicate : toutes les permutations seraient identiques.
  • Permuter les observations dans chaque groupe au lieu des étiquettes : cela ne change rien à la statistique.

Pour aller plus loin. Remplace la différence de moyennes par la différence de médianes : le test reste valide sans autre modification. C’est l’idée générale pour tester une statistique dont on ne connaît pas la loi, y compris un indice de ségrégation ou un Gini.

Comparaisons multiples : Bonferroni et Holm

Marche 4 sur 4 · Autonome

mult1 = { const g = rng("stats-mult-1", salt); return { seed: g.int(1, 9999), m: g.pick([10, 20, 40]) }; }

On effectue tests au seuil de 5 %. Dans d’entre eux, il n’y a aucun effet réel ; dans deux, il y en a un vrai (p-values très petites). Combien de « découvertes » obtient-on sans correction, avec Bonferroni, avec Holm ? Écris les deux corrections de p-values.

AstuceIndice 1 · par où commencer

Quand on teste beaucoup d’hypothèses, quelques tests « sortent » par hasard. Pour que le risque d’au moins un faux positif reste de 5 %, il faut rendre chaque test plus exigeant. Bonferroni le fait de façon uniforme ; Holm de façon séquentielle, en partant de la p-value la plus petite.

AstuceIndice 2 · les corrections

Bonferroni : pmin(1, length(p) * p). Holm : trie les p-values, multiplie la plus petite par \(m\), la suivante par \(m-1\), etc. : (m - seq_len(m) + 1) * p[o].

AstuceIndice 3 · la fonction R, sur un exemple

order(p) donne les positions qui trient p ; seq_len(m) donne les rangs 1 à m. Tu peux vérifier tes fonctions avec p.adjust(p, "bonferroni") et p.adjust(p, "holm"). Exemple :

p <- c(0.04, 0.001, 0.2); m <- length(p)
o <- order(p)                        # positions triées
pmin(1, m * p)                       # Bonferroni
(m - seq_len(m) + 1) * p[o]          # facteurs de Holm sur les p triés
p.adjust(p, "holm")

Raisonnement.

  1. Avec \(m\) tests indépendants à 5 % et H0 vraie partout, on attend \(0{,}05\,m\) faux positifs, et la probabilité d’en avoir au moins un est \(1 - 0{,}95^m\) : 64 % pour \(m = 20\), 87 % pour \(m = 40\).
  2. Bonferroni : \(p^{\mathrm{aj}}_i = \min(1,\; m\,p_i)\). Il contrôle le FWER (probabilité d’au moins un faux positif) mais devient très conservateur quand \(m\) est grand.
  3. Holm : on trie les p-values croissantes, \(p_{(1)} \le \dots \le p_{(m)}\), et on pose \(p^{\mathrm{aj}}_{(k)} = \max_{j \le k}\big[(m-j+1)\,p_{(j)}\big]\) (plafonné à 1). Le cummax impose la monotonie. Holm contrôle le même FWER sans hypothèse supplémentaire et rejette toujours au moins autant que Bonferroni.
  4. aj[order(o)] ramène les valeurs ajustées dans l’ordre initial (order(o) est la permutation inverse de o).
  5. Quand on explore beaucoup d’hypothèses et qu’on accepte quelques fausses découvertes, on préfère contrôler le FDR (Benjamini-Hochberg, p.adjust(p, "BH")) : c’est la proportion de fausses découvertes parmi les rejets qui est maîtrisée.
set.seed(mult1$seed) m <- mult1$m p <- c(runif(m - 2), 0.0004, 0.003) bonf <- function(p) pmin(1, length(p) * p) holm <- function(p) { m <- length(p); o <- order(p) aj <- (m - seq_len(m) + 1) * p[o] aj <- pmin(1, cummax(aj)) aj[order(o)] } c(sans_correction = sum(p < 0.05), bonferroni = sum(bonf(p) < 0.05), holm = sum(holm(p) < 0.05), somme_bonf = sum(bonf(p)), somme_holm = sum(holm(p))) 
set.seed(mult1$seed)
m <- mult1$m
p <- c(runif(m - 2), 0.0004, 0.003)
bonf <- function(p) pmin(1, length(p) * p)
holm <- function(p) {
  m <- length(p); o <- order(p)
  aj <- (m - seq_len(m) + 1) * p[o]
  aj <- pmin(1, cummax(aj))
  aj[order(o)]
}
c(sans_correction = sum(p < 0.05), bonferroni = sum(bonf(p) < 0.05), holm = sum(holm(p) < 0.05),

Pièges fréquents.

  • Oublier pmin(1, ...) : une p-value ajustée dépasserait 1.
  • Oublier cummax : les p-values ajustées ne sont plus monotones et l’on peut rejeter une hypothèse moins significative qu’une hypothèse acceptée.
  • Oublier de remettre les valeurs dans l’ordre initial : les p-values ajustées ne correspondent plus aux bons tests.
  • Faire plusieurs analyses, ne retenir que celle qui « sort » et ne corriger que celle-là : on ne peut corriger que ce que l’on a déclaré avoir testé (p-hacking).

Pour aller plus loin. Simule 1 000 jeux de 20 p-values sous H0 : la proportion de jeux avec au moins un \(p < 0{,}05\) vaut environ 64 %, contre environ 5 % avec Holm. Compare enfin tes fonctions à p.adjust(p, "bonferroni") et p.adjust(p, "holm").

Bayes : valeur prédictive d’un test

bayes1 = { const g = rng("stats-bayes-1", salt); return { prev: g.pick([0.5, 1, 2, 5, 10]), se: g.pick([90, 92, 95, 98, 99]), sp: g.pick([90, 92, 95, 97, 99]) }; }

Une maladie touche % de la population. Le test a une sensibilité de % (positif si malade) et une spécificité de % (négatif si sain). Quelle est la probabilité d’être malade quand le test est positif (VPP) ? D’être sain quand il est négatif (VPN) ?

AstuceIndice 1 · par où commencer

Imagine 100 000 personnes et dresse un petit tableau : combien de malades ? Parmi eux, combien de positifs ? Combien de positifs parmi les sains ? Le calcul de Bayes est ce tableau lu en colonne.

AstuceIndice 2 · la formule

\(P(M \mid +) = \dfrac{P(+ \mid M)\,P(M)}{P(+ \mid M)\,P(M) + P(+ \mid \bar M)\,P(\bar M)}\), où \(P(+ \mid \bar M) = 1 - \text{spécificité}\). Même démarche pour le VPN.

AstuceIndice 3 · la fonction R, sur un exemple

Pose les quatre cases d’un tableau 2 × 2 en probabilités : vrais positifs se * prev, faux négatifs, faux positifs (1 - sp) * (1 - prev), vrais négatifs. La VPP est la part des positifs qui sont de vrais positifs. Exemple (autres valeurs) :

prev <- 0.1; se <- 0.9; sp <- 0.8
vrais_pos <- se * prev
faux_pos  <- (1 - sp) * (1 - prev)
vrais_pos / (vrais_pos + faux_pos)      # P(malade | positif)

Raisonnement.

  1. Sur 100 000 personnes, \(\text{prév} \times 100\,000\) sont malades, les autres sont saines.
  2. Parmi les malades, la sensibilité donne les vrais positifs ; parmi les sains, \(1 - \text{spécificité}\) donne les faux positifs.
  3. \(\text{VPP} = \dfrac{\text{vrais positifs}}{\text{vrais positifs} + \text{faux positifs}}\), c’est la formule de Bayes écrite avec des effectifs.
  4. Même logique pour la VPN, avec les négatifs : vrais négatifs = spécificité × sains, faux négatifs = \((1 - \text{sensibilité})\) × malades.
  5. Quand la maladie est rare, les faux positifs (issus d’un grand nombre de sains) dominent les vrais positifs (issus d’un petit nombre de malades) : la VPP est modeste même avec un bon test.
prev <- bayes1$prev / 100; se <- bayes1$se / 100; sp <- bayes1$sp / 100 vpp <- se * prev / (se * prev + (1 - sp) * (1 - prev)) vpn <- sp * (1 - prev) / (sp * (1 - prev) + (1 - se) * prev) c(VPP = vpp, VPN = vpn) 
prev <- bayes1$prev / 100; se <- bayes1$se / 100; sp <- bayes1$sp / 100
vpp <- se * prev / (se * prev + (1 - sp) * (1 - prev))
vpn <- sp * (1 - prev) / (sp * (1 - prev) + (1 - se) * prev)
c(VPP = vpp, VPN = vpn)

Pièges fréquents.

  • Confondre \(P(+ \mid M)\) (sensibilité) et \(P(M \mid +)\) (VPP) : c’est l’erreur du procureur.
  • Oublier de multiplier par la prévalence.
  • Utiliser la spécificité à la place de $1 - $ spécificité pour les faux positifs.

Pour aller plus loin. Calcule la VPP pour une prévalence de 0,5 %, 5 % puis 50 % avec le même test : elle augmente fortement avec la prévalence.

Erreurs fréquentes. (1) ERREUR : objet introuvable : un nom est mal écrit ou défini plus bas. (2) Résultat de longueur 1 au lieu de n : il manque une opération vectorisée ou un mean() en trop. (3) NA : ajoute na.rm = TRUE ou cherche la valeur manquante. (4) Une p-value à 0 : c’est une valeur arrondie, écris « p < 0,001 ». (5) Mettre le résultat dans un print() : la dernière ligne suffit, c’est elle que le correcteur lit.
